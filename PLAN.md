# SoundToTab — план на 12 недель

**Цель:** работающий инструмент `mp3 → .gp5` с дорожками гитары, баса,
барабанов и клавишных + своя обученная модель барабанов с честной метрикой.

**Бюджет времени:** 2–3 часа раз в 2 дня ≈ 8–9 часов в неделю.
**Срок:** 10 учебных недель + установочный вечер + 1–2 буферных ≈ 3 месяца.

**Правило проекта:** 30% теории, 70% практики. Нет коммита — не было сессии.

---

## Словарь

Читать перед неделей 0. Всё, что ниже, — это инструменты, а не теория ML.

| Слово | Что это по-человечески | Когда нужно |
|---|---|---|
| **пакет / библиотека** | набор готового кода, написанный кем-то другим | всегда |
| **pip** | программа, которая ставит пакеты | всегда |
| **venv** | отдельная папка с пакетами только для этого проекта | с недели 0 |
| **uv** | замена pip + venv: одна программа, быстрее, умеет ставить нужную версию Python | с недели 0 |
| **PyTorch (torch)** | библиотека для нейросетей | с недели 1 |
| **CPU / GPU** | процессор / видеокарта | с недели 1 |
| **CUDA** | технология NVIDIA, чтобы считать на видеокарте | с недели 6, только на ПК |
| **CUDA-сборка torch** | вариант пакета torch, умеющий GPU | неделя 6, ПК |
| **nvidia-smi** | команда «покажи видеокарту и драйвер» | неделя 6, ПК |
| **git** | история версий файлов, можно откатиться | с недели 0 |
| **.gitignore** | список того, что в историю не кладём | с недели 0 |
| **pyproject.toml / uv.lock** | «паспорт» проекта и точные версии пакетов | отложено до недели 8 |
| **ffmpeg** | консольная программа для аудио | неделя 0 |
| **librosa** | библиотека для аудио: загрузка, спектрограммы | неделя 0 |

Два факта про ноутбук, чтобы не пугаться:

1. Системный **Python 3.14** слишком новый для PyTorch. Внутри проекта будет
   отдельный Python 3.12 — `uv` скачает его сам, систему это не трогает.
2. Ставить пакеты в системный Python на Arch нельзя. Поэтому venv — не
   бюрократия, а единственный нормальный путь.

## Как устроена неделя

Три сессии по 2.5 часа:

| Сессия | Что происходит |
|---|---|
| **A** | 45 мин теории + 1.5 ч маленькое законченное упражнение |
| **B** | 2.5 ч практики на проекте, без теории |
| **C** | доделать + чекпоинт недели + запись в `experiments.md` + коммит |

Плюс «мёртвые» дни по 30 минут: чтение доков, разбор чужого кода, прослушивание
стемов. Без клавиатуры.

**Сессия C не переносится.** Именно она превращает возню в прогресс.

## Правила

1. Пропустил сессию — не догоняй, сдвигай. Буферные недели для этого.
2. Нет сил на 2.5 часа — делай 40 минут. Ноль хуже, чем мало.
3. Не разрывай B и C.
4. Одна неделя — один измеримый результат.
5. Теорию не копить: прочитал 45 минут → сразу применил.
6. Раз в 2 недели — 20 минут на пересмотр плана. Стабильно отстаёшь на
   неделю? Растяни на 14 недель, это не провал.
7. Не смотри 40-часовые курсы. Точечное видео под конкретную проблему.
8. Застрял на 2 часа — упрощай задачу (меньше данных, классов, эпох).
